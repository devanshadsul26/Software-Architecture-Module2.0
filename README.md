# 📚 SMS - Student Management System

A production-grade **microservices-based Student Management System** built with Node.js, Express, MongoDB, and distributed logging. This project demonstrates software architecture principles including microservices, JWT authentication, role-based access control, correlation-based logging, and scalable system design.

---

## 🎯 Project Overview

**SMS** is a comprehensive backend API for managing students, professors, courses, and enrollments. The system is built using a **5-service microservices architecture** with independent databases, JWT-based authentication, and centralized logging with Elasticsearch & Kibana for observability.

**Subject:** Software Architecture and Development  
**Architecture Pattern:** Microservices  
**Key Concepts:** Distributed Systems, JWT, RBAC, Correlation IDs, Winston Logging, Elasticsearch Integration

## 🔐 Authentication & Authorization

### JWT Implementation
- **Algorithm:** RS256 (RSA asymmetric encryption)
- **Key Storage:** RSA public/private key pairs stored in `routes/auth/keys/`
- **Token Distribution:** Via JWKS endpoint (`.well-known/jwks.json`)
- **Token Verification:** Distributed across all services using JWKS URIs

### Role-Based Access Control (RBAC)

```javascript
const ROLES = {
  ADMIN: "admin",
  PROFESSOR: "professor",
  STUDENT: "student",
  AUTH_SERVICE: "auth_service",
  ENROLLMENT_SERVICE: "enrollment_service"
};
```

### Login Endpoints

```bash
# Admin Login (Full Access)
POST /api/login/admin
Body: { "email": "admin@sms.com", "password": "admin123" }

# Professor Login
POST /api/login/professor
Body: { "email": "admin@test.com", "password": "password" }

# Student Login
POST /api/login/student
Body: { "email": "student@test.com", "password": "password" }
```

## 📊 Logging & Observability

### Winston + Elasticsearch Integration

Every service logs to:
1. **Console** - Real-time terminal output
2. **Elasticsearch** - Centralized log storage with correlation IDs
3. **Kibana** - Visual log search and analysis

### Correlation ID Middleware

Each request automatically gets a unique **Correlation ID** (UUID v4) that:
- Generated by `correlationIdMiddleware` on first request
- Passed through all inter-service calls
- Attached to every log entry
- Searchable in Kibana

**Example Log Entry (Kibana):**
```json
{
  "timestamp": "2026-06-02T10:30:00.000Z",
  "level": "info",
  "message": "[GET /api/students] Found 5 students",
  "correlationId": "a1b2c3d4-5678-xxxx-xxxx-xxxxxxxxxxxx",
  "appName": "studentService"
}
```

### Tracing a Request

Search by correlationId in Kibana to see the complete journey:
```
correlationId : "a1b2c3d4-5678-xxxx-xxxx-xxxxxxxxxxxx"
```

# Install for each service

## 🏛️ Software Architecture Concepts

### Microservices Pattern

Each service:
- ✅ Owns its database
- ✅ Exposes REST API
- ✅ Operates independently
- ✅ Communicates via HTTP

**Benefits:**
- Scalability: Scale individual services
- Resilience: One service failure doesn't crash others
- Flexibility: Different tech stacks per service

### JWT Authentication

- **Stateless:** No session storage needed
- **Distributed:** Each service verifies tokens independently
- **Secure:** RS256 asymmetric encryption
- **Scalable:** No shared session state between services

### Correlation IDs

Traces requests across service boundaries:
1. Client hits Auth Service
2. Auth Service generates request ID
3. Auth calls Professor Service with same ID
4. Professor Service logs with correlation ID
5. **Result:** One correlationId = one complete request trace

### Rate Limiting

Login endpoints have rate limiting (10 requests/minute per IP):
```javascript
const limiter = rateLimit({
  windowMs: 60 * 1000,
  max: 10,
  message: "Too many requests..."
});
```

## 🔍 Key Features

### ✨ JWT with JWKS

- Public keys exposed via `.well-known/jwks.json`
- Distributed verification without shared secrets
- Role-based access control built-in

### 📊 Distributed Logging

- Winston logger in every service
- Elasticsearch storage for long-term retention
- Kibana dashboard for searching and visualization
- Correlation IDs for request tracing

### 🛡️ Security

- Password hashing with bcrypt
- JWT token expiration (6 hours)
- Rate limiting on auth endpoints
- Domain verification on token validation
- Role-based access control (RBAC)

### 📈 Scalability

- Independent service scaling
- Shared database (MongoDB) for consistency
- Async request handling with middleware
- Load-balanced architecture ready
